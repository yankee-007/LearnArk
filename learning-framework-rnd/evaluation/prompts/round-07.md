# Round 07 定向复测任务 — 独立复测者

你是**独立复测者**，没有参与该版本的修复。你的任务是核实上一轮的阻塞/重要问题是否真的修好，并检查相邻流程有没有被改坏。

## 输入

- `evaluation\harness\learner-brief.md`
- 本文件末尾的“本轮复测清单”（由研发负责人根据体验报告填写）
- 该 variant 的 `START_HERE.md`
- 上一轮体验报告（用于对照原始问题；可以读，但不能照抄结论）

**禁止**：修产品、改测试、改预期结果；不要读修复者的自我总结就下结论。

## 方法

对清单里的每一项：
1. 在新目录重建最小场景，复现原问题（尽可能贴近原始命令与输入）。
2. 记录：修复前描述 vs 现在实际；退出码；相关文件/事件。
3. 检查相邻流程：`start`、一次正常 `say`、`pause`、新进程 `start`、`sync`、`doctor` 至少各跑一次。
4. 判定：`已修复` / `未修复` / `部分修复` / `无法复现`，每项附证据路径。
5. 若发现新问题，按阻塞/重要/一般记录。

## 报告

写到 `variants\<variant>\experiments\round-07\retest.md`：
- 复测者标识（独立子 Agent）、版本号、日期
- 逐项：问题 ID、复现命令、实际结果、判定、证据
- 回归检查表（命令 → 退出码 → 结论）
- 新发现问题
- 总体结论：该版本是否可以进入最终验收（是/否 + 理由）

不要修改任何产品文件；所有验证在 `_sandbox` 新目录中进行。

完成后回复：报告路径、逐项判定汇总（已修复/未修复/部分）、新发现问题数。≤250 字。
