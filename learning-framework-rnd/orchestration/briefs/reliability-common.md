# 记忆与可靠性工程师简令（四个方向共用）

你负责让所在方向的学习记录**不丢、不重复、可恢复、可交接**，并留下独立可跑的测试证据。
只改本方向目录；不改 `shared/`、其他方向、DSH。

## 必读
- `shared/requirements.md` 第 6、7、8、9 节
- `shared/spec-core.md`
- 本方向 `design.md`、`runtime/`、`tests/`

## 交付
1. `tests/test_reliability.py`（unittest，可单独运行，默认 mock LLM，不联网）覆盖：
   - **中断/半写**：截断快照与 journal 尾行后，`status`/`start` 仍可读，损坏被检测并在输出中说明；`.bak` 恢复路径生效。
   - **重复保存**：同一 `say`/attempt/`artifact` 连续执行 2–3 次，事件数、等级、计数不翻倍。
   - **并发/锁**：两个进程同时执行写命令（用 `subprocess` 并行启动），要么串行成功，要么后者得到明确的锁超时/冲突提示，状态最终一致；不得丢事件、不得重复计数。
   - **过期写入**：`Document` CAS —— 基于旧版本保存必须 `StaleWrite`；命令层遇到时给出刷新提示而不是覆盖。
   - **Git**：分叉远程（本地裸仓库两个克隆同时提交）→ `sync` 必须保留本地提交、报告冲突/需人工处理、绝不 force push；无远程 → 明确 `no-remote` 且本地提交成功；密钥/日志/锁不进入提交。
   - **干净克隆恢复**：裸仓库 → 克隆到新目录 → 只凭项目文件 `start`/`status` 能恢复下一步（新进程）。
   - **时间模拟**：用 `LEARNARK_NOW` 推进到期，验证调度/复习（事件标 `simulated`）。
   - **秘密**：审计提交内容，不含 API key、`.env`、usage 日志。
2. `docs/recovery.md`（中文，600–1000 字）：用户遇到半写、冲突、锁残留、索引损坏、克隆后异常时，逐步该做什么；写明哪些是自动恢复、哪些需要人工。
3. 必要时修 `runtime/` 的可靠性缺陷（不得改 `learncore/`；核心有 bug 要在报告里说明并给最小复现，由主负责人决定是否升 core 版本）。
4. `experiments/CP2-reliability.md`：测试矩阵（场景 × 结果 × 证据路径），并如实写未覆盖项。

## 要求
- 测试必须**真的执行**，不能只断言函数存在；失败就修，修不了如实记录为未通过。
- 每个测试要能独立复现（固定临时目录、清理锁、不依赖已存在项目）。
- 不使用 psutil 等第三方库；只用标准库 + `subprocess`。
- 并发测试在 Windows 上要稳定：使用 `file_lock` 的超时与重试语义，避免假失败；遇到环境限制要写明。

## 报告
回复：新增/修改文件、测试通过情况（逐项）、发现并修复的真实缺陷、仍未解决的风险。不超过 350 字。
