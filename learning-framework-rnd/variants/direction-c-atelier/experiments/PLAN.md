# Atelier 方向实验计划（8 轮）

版本 0.1.0 · 依据 `research-plan.md` §6 与 `design.md` §12 · 计划日期未执行前一律标“未开始”

## 0. 使用规则

- 每轮 = 一个可证伪假设 → 一次实现/场景变更 → **独立上下文**体验者跑场景 → 反馈分诊 → 修复 → 另一独立 Agent 复测 → 落证据。只跑测试或只改文案不计轮次。
- 体验者不读 `design.md`、源码、历史报告；只拿场景卡与 `START_HERE.md`。
- 结论只能是 `通过 / 失败 / 未测试 / 不适用（须说明理由）`，附版本、证据路径、复测日期。
- 交互预算：每场景 ≤12 次师生往返，超预算即停止并记录未完成原因。
- 失败不隐藏：轮次、失败版本、证据全部保留；不放宽阈值、不删测试来消除失败。
- 目录约定：`experiments/round-0N/` 存该轮体验与复测报告；`evaluation/` 存最终验收。

## 3. 主要指标定义（每轮复算）

- **重复教学次数**：同一 `activity_id` 被两位导师各布置一次，或同一被标记类比（归一化哈希）出现在两轮回复中，计 1 次。
- **矛盾安排次数**：两次会话给出的下一步不一致，或 coach 改动生效但无 `plan_change`，计 1 次。
- **交接填充率**：必填字段非空比例；与 `handoff_degraded` 次数一起报，避免“填满但无用”被误判为成功。
- **上下文成本**：`context_manifest.chars` 的均值、最大值、切换首轮与稳态比。
- **负担**：每场景师生往返次数、命令数、需阅读文档处数（体验报告内置项）。

## 4. 每轮记录的必备字段

轮次、版本（`version-manifest.json`）、日期、假设、变更文件、场景与体验者标识、命令序列、通过/失败结论、证据路径、未关闭问题（严重度：阻塞/重要/一般）、复测者与复测日期、下一轮入口任务。
