# LearnArk 共享产品需求（所有方向必须满足）

版本：req-v1（2026-11-04）
适用：`variants/direction-*` 全部方向。方向可以增加能力，不能删减本文件的底线。

## 1. 产品意图

把“长期学习一个目标”当作一个可维护的项目：

- 一个学习目标 = 一个独立项目文件夹，可单独开、单独备份、单独同步。
- 项目里有多个导师（角色或会话），分别负责规划、概念讲解、练习辅导、考核、复习；具体分工由方向决定，但必须真实存在并可切换。
- 导师围绕同一目标协作；切换导师、换会话后必须能接续，不得产生互相矛盾的安排。
- 最重要的是持久记忆：学过什么、哪里不会、做过什么、用过什么帮助、下一步做什么。
- 退出后重开、换会话、换导师、换设备，都能恢复学习。
- 框架与学习记录通过 Git 同步；状态必须明确区分“已写入文件 / 已本地提交 / 已推送远程”。
- 用户只发一句话启动（如“开始学习”“继续学习”“今天只有二十分钟”），不依赖后台唤醒。
- 学习流程可迁移到其他主题，不得写死为编程课。
- 由系统管理记录和交接，让学习者把时间花在学习上。

## 2. 学习者与主题

- 首个主题：Agent 开发。学习者自述：接触过 Python、API 调用，借助 AI 做过 RAG。**自述不等于能力**，系统必须通过行为证据校准。
- 学习时间：每周 10–20 小时，单次可能只有 20 分钟。
- 第二主题（迁移验证）：英文工作邮件写作，范围小、非编程。必须重新定义任务与评价标准，不能只换标题。
- 研发期使用模拟学习者；最终必须留下真人可直接使用的入口。

## 3. 不能省的底线功能

| 编号 | 底线 | 最低可观察要求 |
| --- | --- | --- |
| R1 | 多导师 | 至少 3 个职责不同的导师/会话，可切换，切换有交接记录 |
| R2 | 持久记忆 | 目标/约束、计划与下一步、能力判断及依据、尝试与作品、帮助程度、错因与复习安排、最近交接 |
| R3 | 一句话启动 | 单条命令/单句输入即可开始或继续，且能定位到正确任务 |
| R4 | 恢复 | 新进程、新会话、干净克隆都能仅凭项目文件恢复 |
| R5 | Git 同步 | 只提交项目文件；区分 written/committed/pushed；不 force push |
| R6 | 跨主题 | 非编程主题能完成“启动→活动→反馈→保存→恢复”最小闭环 |
| R7 | 证据纪律 | AI 代做、看过、跟随完成 ≠ 独立掌握；推测不得写成事实 |
| R8 | 可靠性 | 重复保存不重复计数；中断不产生半写状态；冲突/损坏可检测、可恢复、不静默丢记录 |

## 4. 技术约束

- Python 3.10+，**仅标准库**；Windows 优先，路径必须跨平台。
- 每个方向自包含：`variants/<id>/runtime/` 内有 vendored `learncore`（固定 `CORE_VERSION`），不运行时引用其他方向或 `shared/`。
- 无网络也能进入“离线导师”模式（`LEARNARK_LLM=mock`），用于确定性测试和断网降级；离线模式必须在输出中明确标注。
- 密钥只从环境变量读取（`DEEPSEEK_API_KEY` 或 `LEARNARK_API_KEY`），禁止写入项目状态、日志、提交。
- 所有输出 UTF-8；中文可用。
- 不修改 DSH 本体，不创建公开仓库，不扩大账号权限。

## 5. 导师输出契约

导师（LLM）每轮必须输出自然语言教学回复，并在末尾给一个机器块：

```learn-update
{"help_level": 0, "attempt": {"activity_id": "…", "correct": false}, "misconception": "…", "next": "…", "mastery_delta": 0}
```

- `help_level`：0 独立 / 1 小提示 / 2 分步引导 / 3 基本代做。
- 运行时要校验并只应用合法字段；无机器块、JSON 非法、字段越界都要记录为事件，不能静默丢弃，也不能“按导师说的算”。
- 导师不得声称“掌握了”；掌握判定由运行时的证据规则决定（见第 6 节）。

## 6. 证据与掌握规则

- 来源分级：`self_report`（学习者自述）< `observed`（运行时观察到的行为）< `verified`（独立完成 + 可复现产物/复测通过）。自述不得自动升级。
- 只有 `help_level <= 1` 的正确尝试可以提升能力等级；`help_level >= 2` 的记录为“受助完成”，只证明接触过。
- 单轮最多 +1 级；同一活动重复提交同一答案不得重复加分（幂等键）。
- 能力下降允许发生（遗忘/复测失败），必须记录原因和时间。
- 任何“完成/掌握”标记都必须能追溯到具体事件 ID 和产物路径。

## 7. 可靠性要求

必须处理并测试：

- 中断：进程在写状态时被杀，重开后状态一致（原子写 + 追加日志）。
- 重复保存：同一条命令跑两次，进度不翻倍。
- 过期写入：两个写入者基于旧版本写，必须拒绝后写者并提示刷新，而不是覆盖。
- 冲突：Git 远程分叉时保留本地成果，停止并给出恢复步骤，不 force push、不 reset --hard。
- 损坏：状态 JSON 损坏可从 `.bak` 恢复；日志尾部半行可忽略；去重索引损坏可重建。

## 8. 会话与交接

- 每次学习产生一个会话记录（`sessions/`），包含：导师、开始/结束时间、活动、学习者消息、导师回复、帮助等级、应用的状态变更。
- 会话结束（`pause`/`stop`）必须写交接摘要（`handoff`）：上次停在哪、试过什么、哪里不稳、下一步、未决问题。
- 新会话只通过项目文件恢复上下文，不依赖旧聊天记录。
- 导师切换必须留下 `handoff` 事件（从谁到谁、为什么、未决事项），并在下一导师上下文中出现。

## 9. 同步要求

- `init` 建立/复用 git 仓库与 `.gitignore`（排除 `.env`、密钥、缓存、锁、usage 日志）。
- `sync` 只提交项目内允许路径；报告必须区分 written / committed / pushed。
- 无远程时：本地提交成功，明确说明“无远程，真实 GitHub 同步未验证”。
- 远程分叉：先 pull --rebase；失败则中止变基、保留本地、输出人工恢复步骤。
- 多方向数据不得互相提交：每个项目独立仓库或独立目录，提交信息带项目 slug。

## 10. 明确不做

- 不做后台定时唤醒、不做账号系统、不做云服务、不做移动端。
- 不声称已验证长期学习效果；模拟学习者数据只证明系统行为，不证明真人收益。
- 不用 mock/静态示例冒充真实体验。
