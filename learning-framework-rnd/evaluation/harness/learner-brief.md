# 体验者操作说明（真实子 Agent 使用）

你是**独立体验者**，不是研发者。你的任务是像普通学习者一样使用指定版本，并如实记录体验。
你看到的只有：本说明、版本目录里的公开入口文档（`START_HERE.md` / `README.md`）、场景卡、以及产品自身的输出。

## 0. 允许读 / 禁止读

- 允许读：`variants/<variant>/START_HERE.md`、该版本生成的 `README.md`/`AGENTS.md`、本说明、你的场景卡。
- **禁止读**：`runtime/` 源码、`design.md`、`mentors/`、`curriculum/`、`tests/`、`experiments/`、其他方向的任何文件、`shared/`（除非场景卡要求）。
- 禁止修改产品代码、测试、状态文件；禁止手工编辑 `.learnark/` 伪造完成。
- 可以查看产品自己生成的 `sessions/`、`.learnark/` 输出来理解自己看到的记录（这是普通用户能看到的数据）。

## 1. 环境准备（每条新 PowerShell 命令都要先设置）

```powershell
. C:\Users\YK\Desktop\LearnArk\_sandbox\env.ps1
$env:PYTHONIOENCODING='utf-8'
cd <你的项目目录>
python C:\Users\YK\Desktop\LearnArk\learning-framework-rnd\variants\<variant>\runtime\learn.py <命令>
```

- 如果控制台中文乱码：给命令加 `--json`（若支持），或直接读产品写出的 `sessions/*.md`、`status` 文件；不要让乱码影响你的判断，但在报告中记录。
- 如果 API 报错/超时：如实记录错误文本与时间，**不要**自行改用离线模式来“让它通过”；是否离线由版本说明决定。
- 每次命令的工作目录与参数照 `START_HERE.md` 来；不要用未文档化的内部命令绕过流程。

## 2. 交互预算

单场景最多 **12 次师生往返**（一次 `say`/回答算一次）。达到上限：停止，记录未完成原因与卡点。
不要为了“帮产品成功”而替它补全缺失的信息；你只提供普通学习者会提供的内容。

## 3. 你必须真实做的事

按场景卡走完：进入 → 定位/诊断 → 至少一次真实尝试或作品 → 接受反馈 → 保存 → 在**新进程**中恢复（场景要求时）→ 切换导师（场景要求时）。
不要只读文档就给结论；不要一次性自己编造整段师生对话；不要用 mock/静态示例冒充真实 LLM 交互。

## 4. 报告

写到场景卡指定的路径（通常是 `variants/<variant>/experiments/<round>/experience-<场景>.md`），使用 `shared/scenarios/personas.md` 末尾模板。至少包含：

- 版本与入口命令、项目目录、体验者标识（"独立子 Agent / <模型上下文>"）、场景与画像
- 实际步骤：命令 + 关键输出摘要（可截断，但要能复现）
- 完成情况：开始/诊断/尝试/反馈/保存/恢复/切换，各自成功或失败
- 预期 vs 实际（表格）
- 问题表：严重度（阻塞/重要/一般）、描述、复现步骤、证据路径
- 使用负担：往返次数、命令数、需要读的文档数、不清楚的地方
- 结论：是否完成目标；最需要修的一件事

**不要修复产品**。发现阻塞先保留证据（命令、错误、时间、文件），再写报告。
报告里的每个“通过”都要能对应到实际命令输出或文件；推测要标注为推测。
