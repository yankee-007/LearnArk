# 模拟学习者与体验场景卡（scenarios-v1）

体验者只拿到本文件对应的一张场景卡、版本入口（`START_HERE.md` / `README.md`）和报告路径。
**不提供**内部架构、设计文档、源码、标准答案或“应该已修好”的结论。

## 场景卡

> 每张卡有交互预算：**最多 12 次师生往返**（一次 `say` 或等价输入算一次）。达到上限即停止并记录未完成原因。

### S1 初次进入（P1，30 分钟）
- 情境：第一次用这个学习框架，目标是用 Python 做出能调用工具的小 Agent。上次没用过任何同类工具。
- 要做：从公开入口开始 → 完成首次进入/诊断 → 至少提交 1 次真实尝试 → 结束保存。
- 观察：开场是否告诉你现在做什么；是否需要研发者指导；第一次卡住点。
- 报告写到：`variants/<variant>/experiments/<round>/experience-S1-P1.md`

### S2 诊断与错误反馈（P2，20 分钟）
- 情境：自认为懂 Agent，实际没写过。想验证“它能不能看出我不会”。
- 要做：正常开始 → 当导师让你解释/动手时，给出**你真实会写的答案**（可以有错，例如把 tool call 的返回当作用户消息、把向量检索说成“Agent 的记忆模块”）→ 接受反馈 → 再试一次。
- 观察：是否被泛泛表扬；错误是否被具体指出；提示是否逐级；帮助等级是否可见。
- 报告：`experience-S2-P2.md`

### S3 导师切换与中断恢复（P3，两段各 10 分钟）
- 情境：上次学到一半被打断，今天先有 10 分钟，晚上再有 10 分钟。
- 要做：第一段学 3–5 轮 → 主动结束（保存/暂停）→ **关闭当前进程** → 新进程中仅凭项目继续 → 换一个导师继续 → 再结束。
- 观察：恢复是否重复已学内容；切换后安排是否冲突；是否知道为什么换导师。
- 报告：`experience-S3-P3.md`

### S4 Git 同步与干净克隆恢复（P3）
- 情境：想在另一台电脑继续。
- 要做：按公开说明 sync → 把项目克隆/复制到新目录（模拟新设备）→ 只在新目录用公开入口继续一次 → 报告 written/committed/pushed 是否准确。
- 观察：是否覆盖本地成果；失败时是否给出恢复方法；克隆后是否丢上下文。
- 报告：`experience-S4-P3.md`

### S5 短时与返学（P3，严格 20 分钟）
- 情境：晚上只剩 20 分钟，明天要早起。
- 要做：用“今天只有二十分钟”这类普通表达开始 → 看它给什么任务 → 完成 1 个最小单元 → 结束。
- 观察：是否硬塞长课程；是否能只做一个 5–10 分钟的活动；结束是否有明确下一步。
- 报告：`experience-S5-P3.md`

### S6 跨主题迁移（P4，20 分钟）
- 情境：不学编程，想练英文工作邮件。
- 要做：用公开的模板/参数新建“英文工作邮件写作”项目 → 完成一次诊断或写作任务 → 得到反馈 → 保存 → 重新打开确认记录在。
- 观察：任务、评分标准是否真的变成写作标准；有没有残留编程课内容。
- 报告：`experience-S6-P4.md`

### S7 定向复测（由研发者指定）
- 上一次体验发现的阻塞/重要问题，修复后由**未参与修复**的体验者复测；同时检查相邻流程（启动、保存、恢复）回归。
- 报告：`experience-S7-retest-<persona>.md`

### S8 最终新体验者（全新上下文）
- 只读 `START_HERE.md`，不看设计文档、源码、过往报告。
- 10 轮内完成：开始 → 一个真实活动 → 提交尝试 → 得到反馈 → 保存 → 新进程恢复。
- 报告：`evaluation/final-fresh-user-tests/<variant>-fresh.md`
